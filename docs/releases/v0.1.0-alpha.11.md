INVAR v0.1.0-alpha.11 (prerelease)

Release commit: ffca8aa plus the batch 8 corpus record.

## New rule, honestly labeled

F1 default-switch: a default version or format selector (assignment,
defaultValue, call argument, quoted key) whose value set gains a new value
between producer base and head turns a would-be HOLDS into NOT FULLY
EVALUATED. F1 never claims VIOLATED.

On held-out batch 8, F1 changed nothing: the alpha.10 and alpha.11 engines
give identical verdicts on all 18 cases. The one default-switch case in the
batch (Cargo.lock v4, r1-113) was missed by both: the selector value is an
enum variant, outside F1's frozen value grammar. F1 is the third rule in a
row (after D1 and E1) with zero held-out effect.

## The measured content: the corpus

- Batch 8 held out (r1-104..r1-121): 15 real in-scope breaks, 3 controls.
  8 caught, 1 NOT EVALUATED, 6 missed (5 silent); controls clean.
- All held-out batches (4 to 8): 38 of 70 in-scope real breaks caught, 46%
  missed. The gate for any reliability claim is 20% missed or fewer.
  R1 remains FALSIFIED.
- Next target: widen the default-switch grammar to enum-variant selector
  values (new frozen spec before batch 9).

## Unchanged

Lock format 1, exit codes, signing, and the SHA-pinned Action are unchanged.
