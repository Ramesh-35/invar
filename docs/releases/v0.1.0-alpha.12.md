INVAR v0.1.0-alpha.12 (prerelease)

## New: A2 evidence receipts, gate met

`invar check --receipt <path>` writes a canonical, byte-deterministic
evidence receipt: every input content-addressed by BLAKE3 (remote and local),
the evaluation date recorded as an input, engine version and active rules
stated, verdict and exit code recorded, the whole body sealed by its own
BLAKE3 footer. `invar verify-receipt <path>` re-runs the evaluation and
byte-compares: exit 0 reproduced, 1 not reproduced (input drift, bad
signature, or mismatch, each named), 3 error. `--artifacts <dir>` verifies
fully offline; `--signers <file> --principal <name>` checks a detached SSH
signature (ssh-keygen -Y, namespace invar-receipt). No new dependencies.

Gate, measured: receipts generated on Linux and macOS in CI are
byte-identical for all 122 corpus configs, and every receipt verifies with
exit 0 (run 38047172189). A receipt proves reproducibility of the
evaluation, not correctness of the code and not honesty of the producer;
the docs say exactly that.

## Unchanged

Detection rules are identical to alpha.11: rule expansion is frozen
(founder adjudication after batch 8), held-out record 38 of 70 caught, R1
remains FALSIFIED. Lock format 1, exit codes, release signing and the
SHA-pinned Action are unchanged.
