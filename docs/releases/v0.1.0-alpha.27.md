# v0.1.0-alpha.27: `invar backtest`, proof from your own git history

Lands at: docs/releases/v0.1.0-alpha.27.md

New command: `invar backtest [--config] [--contract] [--depth N=50]
[--format text|json]`. For each locked binding it replays today's
extraction over the producer file's past commits (git subprocess, local
only, zero network) and reports, by commit hash and date, when the bound
field was absent from the producer's extracted surface, with absence
windows counted after the field's first appearance.

Honest scope, stated in the output coda: timelines replay today's
extraction over past file contents; they are not replayed verdicts
(waivers, selectors and samples are today's, and a past consumer may not
have read the field yet). Unreadable or unextractable commits are
stated, never guessed; remote (github:/gitlab:) producers are skipped
and stated; renames are not followed in this version. Exit codes: 0
replayed clean, 4 replayed with stated blind spots, 3 error (including
"not inside a git repository"). Never 1 or 2: the past holds no verdict.

One extraction path: backtest calls the same `source_fields` the checker
uses (made pub(crate)), so the historical surface is computed by exactly
the code that computes today's.
