# v0.1.0-alpha.26: the MCP agent surface grows to four read-only tools

Lands at: docs/releases/v0.1.0-alpha.26.md

`invar mcp` now serves `dependents` and `coverage` beside `check` and
`contract`. All four tools are read-only (readOnlyHint stated); the
server's never-writes-files guarantee is unchanged, which is why `init`
is not a tool. A failed tool call is an MCP error result labeled "not a
verdict", and the server exits 0 at EOF, never through the verdict codes.

- `dependents` (args: query, locks, optional producer): the A4 local
  primitive over MCP. Same rendering path as
  `invar dependents --format json`; relative `locks` paths resolve
  against the invar.toml directory; zero network by construction;
  unreadable lockfiles stated in parse_errors, never dropped.
- `coverage` (optional arg: contract): evaluation disclosure with reason
  codes and the measured record. Same rendering path as
  `invar coverage --format json`. Never a verdict.

Proof of the one-rendering-path claim: test 47 runs the CLI and the MCP
server as separate binary invocations on the same fixture and asserts
the parsed JSON documents are equal, for both tools.
