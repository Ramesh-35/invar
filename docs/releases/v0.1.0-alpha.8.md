Release commit: 0a7de0b947e6aa34fc79f9ab726a478e64768b57

## New: hardening against moved tags

The threat is the tj-actions/changed-files attack (CVE-2025-30066): tags
repointed to a commit that leaked CI secrets.

- Pin this Action by full commit SHA:
  `uses: Ramesh-35/invar-platform@0a7de0b947e6aa34fc79f9ab726a478e64768b57 # v0.1.0-alpha.8`.
  Pinned to a release commit, it downloads that release and verifies its
  checksum and SSH signature; pinned to any other commit, it builds from that
  exact source. Pinned by tag, it works and warns on every run.
- New input `release_token`: used only to download the signed binary, for
  callers whose `github_token` cannot read this repository.
- This repository's own workflows pin every third-party action to a commit
  SHA, enforced in CI; CI runs with read-only contents.
- See docs/reference/ACTION-HARDENING.md.

## Not done

Release tags are not protected by a ruleset: GitHub requires Pro or a public
repository for rulesets on this repository. A tag here can still be moved by
the owner account; pin by SHA.

## Unchanged

Engine identical to alpha.6/alpha.7 apart from the version. Detection on
held-out data: 13 of 25 real in-scope breaks caught (48% missed); R1 remains
FALSIFIED.
