# v0.2.32: judge a schema change from inside a coding agent

## New: the `judge` tool in `invar mcp`

`invar mcp` gains a fifth read-only tool, `judge`. A coding agent can now
check a JSON Schema change before committing it:

    judge {"contract": "schemas/order.json"}                       # working tree vs HEAD
    judge {"contract": "schemas/order.json", "base_ref": "origin/main"}
    judge {"base": "a.json", "head": "b.json"}                      # two files

The result is the same JSON document as `invar judge ... --format json`.
It needs no invar.toml and no network. Paths outside the repository and
option-looking refs are refused as errors, never verdicts; nothing a
client sends can set the verdict. Setup and a first workflow:
docs/reference/MCP-INTEGRATION.md.

## Changed verdict: a property added to an open object

Ruled 16 November 2026 (docs/falsification/OPEN-ADD-SPEC.md). Adding a
typed property to an object that accepted any key was reported NOT
EVALUATED (`unchecked_change`, exit 4). It is now VIOLATED (exit 1) when
the judge can confirm a counterexample: an instance that carried another
value under that key, valid before, rejected now. New witness kind:
`added_constrained`. Without a confirmed counterexample the path is NOT
EVALUATED (`undecided_constraint`), listed in `undecided_paths` with the
reason in `undecided_changes`.

## New: every break says what it breaks

Ruled 17 November 2026. A valid counterexample does not show that a real
caller breaks. Every witness now carries `compatibility_scope`:
`DECLARED_INPUT` (instances using what the base declared are rejected) or
`UNDECLARED_PROPERTY_SPACE` (only instances that sent a key the base never
declared are rejected). Also `witness_basis`, `previously_declared`, and
`observed_caller_usage: "UNKNOWN"` with `impact_assessment:
"NOT_ESTABLISHED"`, because the judge never sees callers. Each result has a
`findings` object counting the two kinds apart, and text output adds one
line under the headline. Verdicts and exit codes do not depend on these
fields. There is no severity score. Details: OPEN-ADD-SPEC.md, section r1.

On the 220 real `inputSchema` changes in github/github-mcp-server: 16
changes break declared usage, 67 only restrict undeclared properties, 125
HOLDS, 12 NOT EVALUATED.

What this means for a pipeline that runs `invar judge`: some changes that
exited 4 now exit 1 (67 of the 220 github-mcp-server changes; every one of
them has `category: "UNDECLARED_PROPERTY_RESTRICTION"`, so a pipeline can
tell them apart). No change that exited 0 or 1 before changes exit code
because of this ruling. Exit code meanings are unchanged.

## Evidence

- New tests: `mcp_judge_matches_cli_and_stays_inside_the_repository`
  (both modes, one rendering path with the CLI, refusals),
  `oa_added_property_by_openness` (10 cases), `oa_r1_scope_is_stated_per_witness`,
  and r_f14 amended as ruled.
- Corpus gate on 220 real changes against 0.2.31 and the earlier
  candidate: verdicts, exit codes and every earlier key and value
  unchanged except where ruled; 121 counterexamples confirmed by
  python-jsonschema.
- 25 adversarial OPEN-ADD cases, every counterexample confirmed by an
  independent validator (python-jsonschema 4.26), 0 failures.
- The real Snowplow media_player 1-0-0 to 2-0-0 change (B1 case b1-001),
  judged through the MCP tool from a git repository: VIOLATED with 6
  witnesses, all 6 counterexamples confirmed by the independent validator.

## Not changed

Exit code meanings, reason codes, lock formats and every other tool are
unchanged. Every field 0.2.31 printed is still printed with the same
meaning. The MCP server still never writes files.
