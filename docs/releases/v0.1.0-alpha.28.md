# v0.1.0-alpha.28: A4.1, check states its sibling dependents

Lands at: docs/releases/v0.1.0-alpha.28.md

`invar check` can now state, at the end of its ordinary output, which
sibling invar.lock files bind this repository's producer files: the
producer path, the sibling lockfile, and the binding count, with a
pointer to `invar dependents` for field-level detail. Ratified design
(2026-10-13): the optional `[dependents] locks = "<dir>"` key in
invar.toml (written by users, never by init), overridden by
`invar check --locks <dir>` when both are present.

Scope, stated plainly: this is awareness, not modification detection.
check has no baseline to know what changed; it reports who binds what,
every run where a locks directory is given. Hard constraints held: the
scan never leaves the given directory, performs zero network calls,
excludes the repository's own invar.lock, and NEVER changes check's
exit code: sibling parse errors, unresolvable producer refs, and even
an unreadable locks directory are stated in the output instead.

Predictions recorded before the build (outputs/a41-predictions.md) and
their measured outcomes: C1 through C6 ALL CONFIRMED by test 49, which
measures exit-code identity across flag, config, override, and
unreadable-directory runs, the own-lock exclusion, the binding count,
and that a [dependents] section changes nothing else. One build error
before first green: the sibling block initially used a moved base_dir
binding (borrow error); fixed by recomputing it, no logic change.

Tests: 49/49 (was 48). New: 49 a41_check_states_sibling_dependents.
