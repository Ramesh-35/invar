# v0.1.0-alpha.29: init no longer emits duplicate contract ids

Found by Experiment B (docs/falsification/experiment-b/), a seeded
first-run test on 30 public monorepos. When two producer files shared a
basename (schema.json in several directories), `invar init` gave their
contracts the same id. `invar lock` keys contracts by id, kept one, and
the stranger's first `invar check` failed with exit 3 and an error
blaming their lock. Ids are now unique: non-colliding ids are
byte-identical to before (no existing manifest changes); a collision
gets a deterministic `#2`, `#3` suffix in discovery order.

Test 50 runs init, lock and check on two same-named producers and
asserts distinct ids and no exit 3; it was run against the unfixed
alpha.28 code first and failed there with the exact collision seen in
the wild. 50/50 tests; release build warning-free. Version-only Cargo
changes.

Not changed, stated: init's discovery heuristics are untouched. Its
measured first-run limits (producers found only as schema files;
consumers only via the literal payload.<field> pattern) are recorded in
Experiment B and are the next engineering target, not part of this fix.
