INVAR v0.1.0-alpha.5 (prerelease)

## New: invar.lock (R2)

- `invar lock` records the producer fields your repository reads, each bound to
  its declaring type (`Type.field`), with the producer's BLAKE3 hash, when it
  was fetched (t_r) and when each binding was accepted (t_v).
- `invar check` compares the live producer with the lock and reports removed or
  retyped fields as `Type.field`. It replaces `producer_base`.
- `invar lock --update` accepts a reviewed producer change.
- Waivers in `invar.lock` (`field`, `owner`, `reason`, `expires`) show as
  `WAIVED (N days remaining)` in the PR comment, fail the check once expired,
  and may run at most 90 days.
- `invar mcp`: a read-only MCP server on stdio for coding agents, with tools
  `check` and `contract`.
- `invar fix --suggest`: prints a consumer patch only for an unambiguous 1:1
  field rename in the same type. Never writes files; does not run in CI.
- Java, Kotlin and Ruby artifacts are now SKIPPED (exit 4), like C, C++, C#,
  PHP and Swift. Supported: Go, Python, JS/TS, Rust, and JSON/YAML specs.

## Exit codes

0 hold, 1 violated (only), 2 ledger break, 3 error or LOCK_DRIFT (`invar lock`),
4 skipped (unsupported language).

## What this release does not claim

Detection is unchanged from alpha.4. On a fresh held-out benchmark of 10 real
breaks in Go, Python, JS/TS and Rust, the frozen alpha.4 engine caught 6 and
missed 4 (40%), against a 20% bar: R1 remains FALSIFIED. The lock makes a check
reproducible and reviewable; it does not make it catch more. Extraction is
pattern matching, not a full parser.

Without an `invar.lock`, behaviour is identical to alpha.4 on 48 of 49
benchmark cases; r1-023 (Java consumer) is now SKIPPED instead of PARTIAL.
Reference: `docs/reference/INVAR-LOCK.md`.
